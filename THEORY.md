# A Theory of ctworldgen

## What it models

`ctworldgen` generates the piece of paper a Classic Traveller referee needs before he can run a session: a subsector, which is eighty hexes of a printed grid, some fraction of them carrying a world, each world reduced to a string of eight characters, and lines drawn between the worlds a starship can jump between. The world it models is not "star systems" in any astronomical sense. It is a procedure printed on twelve pages of Book 3 _Worlds and Adventures_ (© 1977), and the thing being modelled is that procedure — its throws, its order, its tables, and the places where it stops short of saying what to do.

That distinction is the whole of the design. The specification is not a behaviour anyone can reason about from first principles; it is a physical page. A generated subsector that is plausible, playable and internally consistent is still wrong if the page says otherwise, and the code has no way to discover this on its own. Everything unusual in the repository follows from taking that seriously.

The domain nouns are `Record`, `World`, `Route`, and `Clamp`; the identity types are `Hex`, `Starport`, `Digit`, `Characteristic`, `Parsecs`, `Grid`, and `dice.Target`. A `Record` is a subsector — or, since ERRATA E006, a sector of sixteen of them on one 32×40 grid — and a `World` is a row inside it. There is no `Subsector` type and no `System` type; the record _is_ the subsector, and this is a decision rather than an omission.

## The load-bearing ideas

**The page is the specification, and the code cannot check itself against it.** No test can tell you that the atmosphere table was mis-transcribed, because the only witness is a PDF a human has to look at. So the repository invests everywhere in making that one class of error expensive to commit: every table is transcribed twice, once into `tables/data/*.json` and once into the test that reads it, so the two must agree; every rule implemented cites its printed page in the code; every error message names the page it enforces. The alpha report singles this out as the reason the output could be trusted at all — "the numbers are the page's numbers" — and it is a user need rather than an engineering preference.

**The font trap is why the double transcription is not paranoia.** The embedded font in the held PDFs maps the em-dash to the glyph `4` and the minus sign to `3`. A text extraction of the jump routes table renders `4 — — —` as `4 4 4 4`, and the size formula `2D − 2` as `2D32`. Both readings are wrong, both look like data, and neither is detectable downstream. This is the single fact that makes `pdftotext` forbidden and a _visual_ read mandatory, and it is why a new table's home is inside the test package as well as the data directory.

**Where the page is silent, the silence is named.** `docs/ERRATA.md` carries eleven readings, E001 through E011, each with its page cite and its stamping condition, and each record carries the list of readings that governed it. The rule is that an ambiguity is never resolved in passing: if you find yourself choosing, you are writing errata. `internal/audit` enforces this bidirectionally — every `E00N` cited anywhere resolves to a heading, and every heading is cited at least once — so a reading cannot be quietly orphaned or quietly invented. The stamping condition matters as much as the reading: E007 and E008 govern the _documents_ rather than the generation, so they are never stamped into a record.

**Dice-stream consumption order is the meaning of a seed.** The engine draws from one PCG stream, and a seed reproduces a subsector only because every throw is made in the same order every time. Two throws are deliberately _not_ made — a size-0 world's atmosphere and a size-0-or-1 world's hydrographics (p. 4) — and rolling a die there and discarding it would shift every world after it. So would reordering any step, adding a step, or generating the sixteen members of a sector concurrently. `EngineVersion` exists to guard exactly this, and the failure mode it guards against is the one corruption undetectable from the file itself: the record still parses, still renders, and no longer reproduces.

**Types carry identity, never rule invariants.** `Hex`, `Starport`, `Digit`, `Characteristic`, `Parsecs` and `dice.Target` are types because each parses at the program's edge and marshals to the string the record prints. Size, atmosphere, hydrographics, population, government, law level and the technological index stay `int`. A `type Atmosphere int` bounded 0–12 would put the p. 5 table's last row into Go source beside the data file and the test that transcribes it — a third copy of a number the book prints once — and it would also be _wrong_, because R14 caps nothing at a descriptive table's last row and a generated atmosphere reaches 15. A range in a type is a rules claim, and a rules claim belongs on a page with a cite.

**Description is a second authority, and a narrower one.** The list of sources in authority for generation is closed, because a seed's meaning depends on it. But pp. 10–11 give a referee ten proper nouns of 1977 shorthand and no sense of the world in front of him, so T5 Core Book 2 pp. 230–232 is cited — named in the document, written down as E011, changing no throw, no record field and no stamp. It is one Far Future Enterprises book glossing another. The permission was taken once, deliberately, and the temptation to widen it whenever a held page is terse is the thing E011's preamble exists to refuse.

**A test that cannot fail looks exactly like one that passes.** This has caught the authors repeatedly and never once as a red suite: assertions defined and never called, a roster check satisfied by the world's own detail page, a parity check run on a fixture with no worlds where every cell is the same width. The discipline that follows is that a new invariant is not done until a deliberate mutation has been shown to kill it — and, because the goldens move under a mutation, that the goldens are regenerated first so the suite fails for the right reason.

**An empty subsector is a result, and there is no log.** Eighty throws that place no world produce a valid record with no worlds and no lanes; nothing rerolls and nothing errors. The record carries outcomes and not the throws that reached them, because the stream is reproducible from the seed and a log would be a second, driftable copy of it.

## The seams

**The record file is the contract, and it faces two ways.** `starmap.Marshal` writes it, `Decode` reads it, `record.schema.json` states it, and `Validate` holds a record to the schema in code because a schema alone rejects nothing at read time. The asymmetry is deliberate: `Decode` calls `Validate` and `Marshal` does not, because the file is the referee's notebook page and he is allowed to hand-edit it. The seam is thin in a specific way — the schema and the checks are two obligations for every field, and either can be updated without the other.

**One package renders two documents, and that is the point.** `render` writes both the Markdown listing and the PDF booklet, sharing `bullets`, `member`/`members`, `legible`, `summary`, `named` and `bases`. The bullet list was once written out twice, agreed by convention, and a change to one was a change the other's tests could not see. Inside one package sharing is the default; across a package boundary it becomes an export decision, which is the pressure that produced the duplication in the first place. The two typesetters are now structurally parallel — `booklet` and `listing` — so that the next thing which must agree between them has an obvious home on both sides.

**The hex grid parity lives in three places and they must agree.** `starmap.Hex.cube`, the text map's `render.gridLine`, and the drawn map's `render.mapFit.hexCenter` each encode which columns sit half a hex low. Getting the offset-to-cube conversion backwards leaves every distance internally consistent and wrong by one for half the map, which no record-against-record test can catch. Each encoding therefore has its own measurement against the printed p. 3 grid, and the test harnesses that take those measurements duplicate one another on purpose: a merged harness compares the three against each other and passes when all three are flipped together.

**A sector is layered on the subsector without disturbing it.** Member _i_ of `sector --seed N` is byte-for-byte the subsector `new --seed N+i` writes. That property is what lets a referee trust a sector at all, and it is why the sixteen are generated in sequence rather than concurrently, and why `gen.seams` stays O(n²) — the loop's visit order _is_ the order the seam stream is drawn in, so a spatial index reaching the same pairs in a different order would write a different sector from the same seed, silently.

**The gate is the seam with the outside world.** `task` is the whole of it, CI runs exactly `task`, and the toolchain is deliberately unpinned so the gate fails when a tool moves rather than drifting behind it. The coverage ratchet is an integer count of uncovered statements per package, failing in both directions, because a percentage holds still while a guarded branch adds one covered statement and one uncovered.

## What the shape accommodates, and what it resists

Easy: **a new descriptive table** — transcribe it twice, add a row to `COVERAGE.md`, and it is done, because `tables` is uniform and the label path is one list feeding both documents. **A new section in either document**, since the shared middle is already factored. **A new reading**, which is an E-number, a stamping condition and a cite. **A new output format** would be a third typesetter over the same record and the same middle.

Hard: **anything that touches the order of throws.** Per-area occurrence DMs (issue #5) was the live example, and how it was built is the pattern for the next one. The obvious implementation — scan one area, then the next — would have visited the hexes out of grid order and silently changed every seed's meaning; the reading instead varies only the number each throw is _read against_, leaving the loop, its order and its eighty dice exactly where they were. That is what made the change additive rather than breaking: `occurrence_areas` is `omitempty` beside `occurrence_dm`, so a record with no areas is byte-for-byte what the tool wrote before the field existed, `schema_version` did not move (the schema's own description already licenses pre-release growth at version 1), and `EngineVersion` did not move because no throw, no order and no construction changed. The proof is that regenerating the four goldens that predate areas produces an empty diff. **Concurrency anywhere**, which the sixteen independent members make a standing temptation. **A world-shaped record**, which could carry neither the grid the occurrence throw is made against nor a lane that needs its neighbours to exist.

A maintainer who held the theory would look first: a wrong distance on half the map → the three parity encodings and their measurements against p. 3, never the conversion in isolation. A record that renders but no longer reproduces → whether a step was added, removed or reordered in `gen`, and whether `EngineVersion` moved with it. A number that disagrees with the book → the data file _and_ the second transcription in the test, and then the page, visually. A check that is suspiciously green → whether a mutation kills it, with the goldens regenerated first.

A maintainer who did not hold it would be most likely to damage things by: reading a table with `pdftotext` and getting numbers that look right; adding a die roll for a characteristic the page skips, "for symmetry"; replacing `gen.seams` with a spatial index on performance grounds; parallelising the sixteen members; introducing a `type Atmosphere int` with the p. 5 range in it; or resolving a silence in the page without an E-number, which is the failure that leaves no trace at all.

## Uncertainties and tensions

I am inferring most of this from the code, the errata and the commit history rather than from the authors, and the following are where I am least sure.

- **`Digit` spans 0–33 while nothing generates above 18.** The alphabet is Book 1 p. 8's hexadecimal extended by Book 3 p. 2's letters, and R15's "it must reach 20" is read as a floor on the notation rather than a bound. That reading is defensible and recorded, but a `Digit` that can hold a value no throw produces is also exactly what an over-general type looks like, and I cannot tell from the code which it is.
- **`Validate` is exported and `Marshal` deliberately does not call it.** The stated reason — the record is the referee's to edit — is coherent, but it means the engine's own write path has no structural guarantee, only the six-hundred-seed sweep in `gen`. If someone added a second writer, nothing would catch it.
- **The error sentinels are mostly unmatched.** Most are the subject of no `errors.Is` anywhere; what they buy is one definition per rule of a message carrying a page cite. That is a real benefit, but a sentinel exists to be matched, and a reader from a more typical Go codebase will read a package of them as an incomplete abstraction rather than as a citation registry.
- **`render`, well over two thousand lines in one package, is defended rather than merely tolerated**, and I believe the defence — but it is the kind of decision that is right until it is suddenly not, and there is no stated size at which it would be revisited.
- **The relationship between `EngineVersion` and the tags is asserted rather than enforced.** Nothing in the gate checks that a change to the dice order moved the number; the guard is entirely a matter of the three conditions in `record.go` being read and honoured.
- **E011's fence is a stated intention.** "Do not widen this" is written down and there is no mechanism behind it — no check distinguishes a T5 citation used for description from one that leaked into a throw. The audit confirms the reading is cited; it cannot confirm the reading was obeyed.

---

The theory, compressed: _ctworldgen models a printed procedure rather than a domain, so fidelity to a page that the program cannot read is the correctness criterion; every silence in that page is named and numbered before it is resolved; the order in which dice are drawn is the meaning of a seed and therefore the one thing that must never move; types carry identity and data carries the book's ranges, so that no number the book prints once is written down twice in Go; and every check is assumed dead until a mutation has been shown to kill it._
